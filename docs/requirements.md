# 麻雀アシストツール 要件定義書 v1.0（確定版）

- 最終更新: 2026-09-12
- 状態: 7章の未決事項をすべて確定。8章に決定記録を残す。

## 1. 概要

- セガNET麻雀MJ（モバイル版）の友人戦で使う、手入力型のアシストWebアプリ
- 局面情報を手入力し、以下の2つを表示する
  - 危険牌アシスト：他家に対する安全牌
  - 役アシスト：役候補・推奨打牌・向聴数

## 2. 利用環境・前提

| 項目 | 内容 |
|---|---|
| MJのプレイ端末 | iPad |
| ツールの利用端末 | iPhone（主）、Mac（副） |
| 開発場所 | Mac上の `my-dev` フォルダ |
| 配信方法 | 暫定で GitHub Pages（9章）。private 化後に再決定 |
| 対局人数 | 4人（自分＋他家3人） |
| 利用場面 | MJの友人戦（対戦相手の了承あり） |

## 3. 対象ルール

ルール設定は対局ごとに切替可能。**切替対象は次の2項目のみ**とし、他はMJ標準固定とする。

| 項目 | 選択肢 | 既定値 | 影響する処理 |
|---|---|---|---|
| 赤ドラ | 0枚 / 3枚（各色の五に1枚） / 4枚（五筒が2枚） | 3枚 | 打点評価、推奨打牌のタイブレーク、牌の残枚数管理 |
| 喰いタン | あり / なし | あり | 役候補の判定（鳴き後の断幺九を候補に出すか） |

MJ標準固定とする項目（UIに出さない）: 裏ドラあり、一発あり、槓ドラあり（即乗り）、ダブロンなし、流し満貫なし、四家立直で流局。
点数計算をしない（6章）ため、これらは役候補の列挙にのみ関係する。

## 4. 機能要件

### 4.1 局開始時の設定

局の切れ目にしか使わないので、対局画面とは別の専用画面にし、3ステップに分ける。
「次の局へ」で来たときは①が自動で埋まっているため、確認して進むだけで済む。

| ステップ | 内容 |
|---|---|
| ① 局 | 自風・場風・局・本場と、ルール設定（赤ドラ・喰いタン）。すべて選択肢をタップして選ぶ。現在の設定を「東3局 2本場 自風 南（子）」のように大きく表示して確認しやすくする |
| ② ドラ | ドラ表示牌を1枚選ぶ。選ぶと導出されたドラを並べて表示し、そのまま③へ進む |
| ③ 配牌 | 自分の配牌を入力する（親は14枚、子は13枚）。残り枚数を表示し、揃うまで「開始」は押せない |

- 実際のドラはツールが導出する（九→一、北→東、中→白 の送りを含む）
- 自風の選択で親／子は自動確定（東家＝親）。必要な配牌の枚数もこれで決まる
- ①では牌を使わないので入力パッドを隠す。②③ではパッドの入力先をステップが決めるため、入力先の切替は要らない
- 入力済みの牌はタップで削除できる。パッドの「1枚戻す」で末尾を取り消せる
- ステップは上部のタブで行き来できる。②を飛ばした場合は③で「ドラ表示牌が未選択です」と出し、開始できないようにする
- 入力の途中でリロードしても、入力済みの内容から再開するステップを決める
- ルール設定（3章）は対局中は変更不可、次局に持ち越す

### 4.2 対局中の入力

**他家（3人分）**
- 捨て牌
- リーチ宣言（宣言牌を横向きとして記録）
- 鳴き（ポン・チー・明槓・加槓。誰から鳴いたかも記録）

**自分**
- ツモ / 打牌 / 鳴き / リーチ / 暗槓

**その他**
- 槓が発生したときの槓ドラ表示牌

**入力方式**
- 自作SVGの牌画像をタップして選択する
- 赤5は赤トグルを押してから牌をタップする

**入力先の自動送り**

打順は決まっているので、次に何を入力すべきかはログから導出できる（`state.expect`）。
通常は入力先を指定せず、牌をタップするだけで進む。

- 打牌 → 次の家の捨て牌 → … → 一周したら自分のツモ → 自分の打牌
- 鳴きが入ったら、鳴いた家の打牌に飛ぶ
- 槓のあと自分の番なら、嶺上牌のツモを先に入力する

これにより1巡の入力は「他家3人の捨て牌3タップ＋自分のツモ1タップ＋打牌1タップ」の
5タップになり、入力先の切替は不要になる。

- 自分の打牌は手牌からでも入力パッドからでも切れる。パッドから切れるので、
  ツモ切りは同じ牌を2回タップするだけで済む
- 鳴きの大半は直前の捨て牌に対して起きるため、捨て牌を入力した直後に
  「誰が」「何を」の2タップで入力できる案内を出す（暗槓・加槓は別途）
- 順番どおりでない入力が必要なときだけ、入力先を手動で指定する。
  手動指定は1回入力すると自動送りに戻る

### 4.3 入力の修正

- 直前の入力を取り消すボタン（操作ログ末尾を削除）
- 任意の巡目・牌をタップして編集（操作ログの該当要素を差し替え）
- 取り消し・編集のあとは状態と画面をログから全再計算する

### 4.4 局の進行

- 「次の局へ」ボタンで「親継続（連荘）／次局」を選び、場風・自風・親・本場を更新する
- 局の入力内容（操作ログ）はリセットし、ルール設定は引き継ぐ

### 4.5 危険牌アシスト

- 判定方式：ルールベース（現物・スジ・壁）。推測は安全度に混ぜない
- **対象：全他家3人に常時表示し、リーチ者を強調する**

#### 4.5.1 安全度の5段階

各他家ごとに、自分が切れる各牌へ次のレベルを与える（1が最も安全）。

| Lv | 名称 | 判定条件 |
|---|---|---|
| 1 | 現物 | その家の捨て牌に同じ牌がある／その家のリーチ後に他家が切って通っている／その牌が場に4枚見えている |
| 2 | 準安全 | 字牌で残り枚数が1枚以下（シャンポンが成立しない）／四〜六で両スジ（両側のスジが現物） |
| 3 | やや安全 | スジ（一・二・三・七・八・九のスジ、四〜六の片スジ）／ノーチャンス（その牌への両面・嵌張の受けが、見えている牌だけで全て否定できる） |
| 4 | やや危険 | ワンチャンス（受けの否定にあと1枚足りない）／残り枚数2枚以上の客風牌 |
| 5 | 危険 | 上記に当たらない無筋の二〜八、および無筋の役牌 |

- 無筋の一・九は、両面での当たり方が片側しかないため Lv4 に置く（当初の表では分類が抜けていた箇所）

- スジの定義：一↔四、二↔五、三↔六、七↔四、八↔五、九↔六。四・五・六は両側が揃って初めて両スジ
- 壁の定義：対象牌を含む両面・嵌張の受け（例：九に対する七八）が、見えている牌の枚数から成立不可能と言えるときノーチャンス、あと1枚で不可能になるときワンチャンス
- 字牌にスジ・壁は適用しない。残り枚数のみで評価する
- 「見えている牌」＝自分の手牌・全員の捨て牌・全員の鳴き・ドラ表示牌

#### 4.5.2 警戒フラグ（安全度とは別枠で表示）

安全度スコアには反映せず、根拠が読めるようにフラグとして並べる。

- リーチ（宣言巡目、一発の有無）
- 役牌ポン → 役あり警戒
- 同色の鳴き2つ以上 → ホンイツ警戒（該当色をフラグに明記）
- ドラ・赤を含む鳴き → 打点警戒
- 二〜八のみの鳴き → タンヤオ／混一以外の手役警戒

#### 4.5.3 最も安全な打牌の決め方

- 各牌について、**3家のうち最も危険なレベルをその牌のスコアとする（最悪値評価）**
- スコアが最小の牌を「最安全牌」として1枚提案する
- 同値のタイブレーク：(1) レベル5と判定した家の数が少ない (2) 現物である家の数が多い (3) ドラ・赤でない (4) 手牌で孤立している牌

### 4.6 役アシスト

- 対象：役満を含む全役
- 表示内容
  - 役候補：**2向聴以内の役（役満は3向聴以内）**を上位5件まで。各候補に向聴数と必要牌を添える
  - 推奨打牌：下記の優先順位で1枚
  - 向聴数（現在の手牌の最小向聴数）
- 喰いタン設定を役候補の判定に反映する

#### 4.6.1 推奨打牌の優先順位

1. 向聴数が最小になる牌
2. 有効牌（受け入れ）の残り枚数が最大になる牌
3. 安全度（4.5.3の最悪値評価）が良い牌
4. 打点（ドラ・赤を残す）

### 4.7 表示ルール

- 最安全牌と推奨打牌が異なる場合は両方を並べて表示し、ユーザーが選ぶ
- 一致する場合は1枚にまとめ、一致していることを示す

### 4.8 画面レイアウト

**iPhone縦持ちで1画面完結**（対局中はスクロール・画面遷移なし）。

## 5. 技術構成・設計方針

- HTML / CSS / JavaScript（ESモジュールで分割、ビルド不要）
- 入力は「操作ログ」として保持し、状態と画面はログから毎回再計算する
  - 取り消し＝ログ末尾の削除
  - 編集＝ログの該当箇所の修正
- 判定ロジック（向聴数・役判定・安全牌判定）は画面から独立したモジュールにする
- 牌画像は自作SVG（文字＋図形でシンプルに）。MJの画像素材は使用しない

### 5.1 操作ログのイベント種別

| イベント | 内容 |
|---|---|
| `init` | 配牌、ドラ表示牌、場風、自風、本場、ルール設定 |
| `draw` | 自分のツモ牌 |
| `discard` | 打牌（プレイヤー、牌、リーチ宣言牌かどうか） |
| `call` | 鳴き（プレイヤー、種別 pon/chi/minkan/ankan/kakan、構成牌、鳴いた相手） |
| `riichi` | リーチ宣言（プレイヤー、巡目） |
| `dora` | 槓ドラ表示牌の追加 |

他家の手牌は不可視なので、他家については `discard` / `call` / `riichi` のみを記録する。

### 5.2 状態の永続化

- 操作ログを1操作ごとに localStorage へ保存し、リロード・アプリ復帰時に復元する
- 「次の局へ」で明示的にクリアする
- 保存形式にバージョン番号を持たせ、形式が変わった場合は破棄して初期状態にする

### 5.3 モジュール構成（想定）

```
src/
  core/
    tiles.js        牌の表現・残枚数管理
    log.js          操作ログとリプレイ（状態の再計算）
    shanten.js      向聴数・受け入れ計算
    yaku.js         役候補の列挙
    safety.js       現物・スジ・壁・安全度5段階
    suggest.js      推奨打牌・最安全牌の決定
  ui/
    board.js        ヘッダー・他家・手牌の描画
    pad.js          入力パッド
    tile-svg.js     牌のSVG生成
```

## 6. 対象外（やらないこと）

- 点数・符計算（MJ本体が表示するため不要）
- 他家の手牌推測・待ち読みの確率計算（安全度はルールベースのみ）
- MJの画面読み取り・自動入力（手入力のみ）
- 対局結果の保存・戦績集計

- 著作権法2条1項9号の5の定義語で、サーバにアップロードし、公衆からのアクセスがあれば自動的に送信される状態に置く行為を指す

- 逆に「公衆」に向けていなければ公衆送信に当たらない。閉じた範囲に限定することには意味がある
- ただし規約上の「頒布」は著作権法の定義と一致する必要はない。規約は当事者間の契約であり、最終的にはセガの解釈・運用が効く

## 8. 決定記録（旧7章「未決事項」）

| 項目 | 決定 | 理由 |
|---|---|---|
| ルール切替の項目一覧 | 赤ドラ枚数と喰いタンの2項目のみ | 判定ロジックに実際に影響するのはこの2つ。他はMJ標準固定で設定画面を小さく保つ |
| ドラの入力方法 | ドラ表示牌を入力し、実ドラを導出。槓のたびに槓ドラ表示牌を追加入力 | 画面に見えているのは表示牌なので、見たままを入れられる。送りの計算ミスを防ぐ |
| スジの扱い | 一・二・三・七・八・九はスジ、四〜六は両スジ／片スジを区別。字牌は対象外 | 片スジと両スジの差は判断に効くため段階を分ける |
| 壁の扱い | 受けの否定が完成＝ノーチャンス、あと1枚＝ワンチャンス。牌種ごとの汎用判定 | 牌ごとに個別ルールを書かず、受けの否定という1つの定義で実装できる |
| 安全度の段階 | 5段階（現物／準安全／やや安全／やや危険／危険） | 3段階では片スジと無筋が同色になり情報が落ちる |
| 最も安全な打牌 | 3家の最悪値で評価し、同値は無筋判定の家の数などでタイブレーク | 放銃回避が目的なので、合計ではなく最悪ケースで見るのが素直 |
| 安全牌リストの対象 | 全他家に常時表示、リーチ者を強調 | 鳴き手・ダマテンを取りこぼさない。序盤は情報が薄く表示も薄くなる |
| リーチ・鳴きの使い方 | 安全度は現物・スジ・壁のみ。鳴き・リーチは警戒フラグとして別枠表示 | 推測をスコアに混ぜると、外れたときに原因が読めなくなる |
| 推奨打牌の決め方 | 向聴数 → 有効牌枚数 → 安全度 → 打点 | 牌効率を主軸にし、同等の選択肢の中で安全を取る |
| 役候補の表示基準 | 2向聴以内（役満は3向聴以内）、上位5件 | 現実的に狙える役に絞る。役満は序盤に見えていることが価値になる |
| 点数・符計算 | 不要 | MJ本体が表示する。実装量を削って判定ロジックに集中する |
| 画面レイアウト | iPhone縦1画面完結（上：アシスト／下：固定入力パッド） | 対局中にスクロールや画面遷移をしたくない |
| リロード時の保持 | localStorage に操作ログを自動保存し復元 | タブ切替や誤リロードで1局分の入力が消えるのを防ぐ |

## 9. 配信方法

**現在の運用: GitHub Pages で公開（暫定）。帰宅後にリポジトリを private へ変更する。**

private 化の際に配信手段を決め直す必要がある。private リポジトリからの GitHub Pages 公開は
GitHub Pro 以上の機能で、Free プランでは private 化した時点で配信が止まる。Pro でも
サイト自体は公開のままなので、7章2項の論点は解消しない。

再決定のときの候補:

| 案 | 公衆への露出 | HTTPS | PWA・オフライン | localStorage | 実運用のコスト |
|---|---|---|---|---|---|
| A. private ＋ Tailscale（`tailscale serve`） | なし（tailnet内のみ） | あり | 可 | 固定ホスト名で安定 | iPhoneにTailscale、対局中はMac起動 |
| B. private ＋ MacのLANサーバのみ | なし（同一LAN内のみ） | なし | 不可 | 動く（`macbook.local` で origin を固定） | 同一Wi-Fi必須、対局中はMac起動 |
| C. private ＋ アクセス制御付きホスティング | 認証の後ろ（友人内に限定） | あり | 可 | 安定 | 第三者サービスへの設置 |
| D. GitHub Pages で公開（現在） | あり（公衆送信可能化） | あり | 可 | 安定 | なし |

前提となる技術的制約:

- ESモジュール（5章）は `file://` では import できない（CORS）。何らかのHTTPサーバが必要
- 単一HTMLにインライン化すれば `file://` でも動くが、iOS Safari の `file://` は origin が不透明で localStorage が不安定になり 5.2 と衝突する
- Service Worker は secure context 必須。`http://192.168.x.x:8000` では使えない
- LAN IP を直打ちすると DHCP でIPが変わったときに origin が変わり localStorage が消える。`macbook.local` 等の固定名を使う

### 7の残り

`yaku.js` は「使える牌の種類を制限した向聴数」で表せる役だけを扱う。この方法は
その制限のもとで手を組んだときの距離をそのまま返すため、対象の役については正確。

- 対応済み: 断幺九、対々和、混一色、清一色、混老頭、七対子、役牌、
  清老頭・字一色・緑一色・国士無双（役満）
- 未対応: 平和、三色同順、一気通貫、一盃口、三暗刻、三色同刻など、
  牌の種類ではなく面子の構造で決まる役。大三元・四喜和のように
  特定の面子を要求する役満も未対応

未対応であることは画面にも表示している。
